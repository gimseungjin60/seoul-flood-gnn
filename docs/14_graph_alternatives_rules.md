# 14. 그래프 보완 실험: 사전 고정 규칙

고정일: 2026-11-09. 센서 고도를 계산하기 전이고, 새 그래프로 어떤 모델도 돌리기 전에 정했다. 코드 기준은 [src/analysis/t2_graph_rules.py](../src/analysis/t2_graph_rules.py)의 상단 docstring과 상수다. 이 문서와 코드가 다르면 코드가 우선한다.
범위: 서울시 강남구 센서 (2026-06-01~08-31, 평가 대상 17개 + 이웃 후보).

## 왜 하나
- 2026 재비교([docs/13](13_2026_recomparison_result.md))에서 도로거리 그래프 GNN은 IDW와 **구분 불가**였고, 선형 모델보다 오차가 컸다.
- 센서별 배수분구 소속은 받을 수 없다는 답을 받았다(2026-11-09). 그래서 [docs/12](12_week10_plan.md) 2-1의 대체 설계 중 B(지형 고도)와 D(대조군)를 쓴다.

## 비교하는 그래프 (2개뿐)
| | 그래프 | 묻는 질문 |
|---|---|---|
| G1 | **고도 방향.** 지금과 같은 도로거리 최근접 5개 중 받는 센서보다 **높은 곳의 이웃만** 남긴다. 높은 이웃이 없으면 5개를 그대로 쓴다. | 물이 낮은 곳으로 흐른다는 정보를 넣으면 나아지는가 |
| G2 | **랜덤 대조군.** 센서마다 무작위로 이웃 5개를 고른다. 그래프 시드 0·1·2를 GNN 시드 0·1·2와 짝지어 평균한다. | 지금 도로거리 그래프의 구조에 의미가 있기는 한가 |

- **바뀌는 것은 이웃 집합뿐이다.** 데이터, 센서 역할, 폴드, 이벤트 13개, GNN 설정(k=5, 은닉 32, 2층, 30에폭, 시드 3개), 가중치 1/도로거리는 2026 재비교와 같다.
- 비교 기준(도로거리 GNN, IDW)은 이미 계산된 2026 예측을 그대로 쓴다.
- **센서 고도:** Copernicus DEM GLO-30(30 m)에서 센서 위치 주변 3×3 화소의 최솟값을 쓴다. 이 DEM은 건물·수목이 포함된 표면 고도라서 도로 위 값을 고르려고 최솟값을 쓴다.
- 고도와 무작위 연결은 관측 없이 정해진다. 수위 상관 같은 관측값으로 엣지를 만들지 않는다.

## 판정 (이 세 가지뿐)
부트스트랩은 2026 재비교와 같다(평가 이벤트 13개를 2000회 복원추출, 시드 0, 타깃 17개 평균, 차이의 95% CI).

| | 비교 | 판정 |
|---|---|---|
| Q1 G1 주 | G1 GNN − 도로거리 GNN | 상한 < 0 "고도 방향 그래프가 나음" / 0 포함 "구분 불가" / 하한 > 0 "고도 방향 그래프가 나쁨" |
| Q2 G1 보조 | G1 GNN − IDW | 상한 < 0 "G1 GNN이 IDW를 넘음" / 0 포함 "구분 불가" / 하한 > 0 "IDW보다 나쁨" |
| Q3 G2 | 도로거리 GNN − G2 GNN | 상한 < 0 "도로거리 구조가 랜덤보다 나음" / 0 포함 "도로거리 구조의 기여 확인 안 됨" / 하한 > 0 "랜덤보다 나쁨" |

- 새 그래프 2개를 비교했다는 사실을 결과와 함께 보고한다. 다중 비교 보정은 하지 않는다.
- G2 GNN − IDW, 센서별 결과, 그래프 시드별 결과는 참고다.
- 결과가 어떻든 보고한다. "고도 정보를 넣어도 차이 없음"도 결론이다.
- docs/13의 판정(P1~P3, S1)은 바꾸지 않는다.

## 순서
1. 이 규칙과 코드를 커밋한다(실행 전).
2. `python -m src.data.sensor_elevation_2026`: 센서 고도.
3. `python -m src.analysis.t2_graph --part diag`: 실행 전 진단(G1 대체 센서 수, G2와 도로거리 이웃의 겹침). 결과를 이 문서에 덧붙인다.
4. `python -m src.analysis.t2_graph --part elev`, `--part rand`: 각 약 50분.
5. `python -m src.analysis.t2_graph_eval`: 판정. 결과는 docs/15에 쓴다.
