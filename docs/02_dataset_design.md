# 02. 데이터셋 구축: 고려사항과 설계

대상: 서울 강남구 하수관로 수위 센서 18개 (대상 지점 20개 중 좌표 확보분), 2025-06-01 ~ 2025-08-31, 1분 간격.
각 항목은 **[확정]** 이미 구현·결정됨, **[미결정]** 결정 필요, **[위험]** 잘못되면 결론이 무효가 되는 지점으로 표시한다.

---

## 0. 설계의 출발점: 어떤 질문에 답하는 데이터셋인가

데이터셋은 모델이 아니라 **질문**에서 출발한다. 이 프로젝트에는 서로 다른 두 질문이 섞여 있다.

| 과제 | 질문 | 입력 | 정답 | 분할 단위 | 현재 상태 |
|---|---|---|---|---|---|
| T1 시간 예측 | 센서가 있는 지점의 10/30분 후 수위는? | 과거 60분 수위 (+강수) | t+h 수위 | 시간 | 구현됨 |
| T2 공간 추정 | 센서를 뺀 지점의 현재 수위는? | 이웃 센서 수위 (+강수) | 그 지점 수위 | **노드** (+시간) | **미구현** |
| T3 위험 판정 | 이 지점이 곧 위험 수위에 도달하는가? | T1/T2 출력 또는 직접 | 초과 여부 | 시간/이벤트 | 정의 없음 |

**[위험]** 프로젝트 목표(센서 없는 곳 추정)는 T2다. 현재 데이터셋은 T1용이다. T2를 위한 분할(노드 단위 holdout)이 없으면 GNN이 "새 지점에 일반화한다"는 주장을 할 수 없다. 두 과제를 같은 문서에서 섞지 말고 별도 데이터셋 스펙으로 관리한다.

## 1. 노드 정의

| 항목 | 현재 | 고려사항 |
|---|---|---|
| 노드 = 센서 지점 | 18개 [확정] | 20개 중 2개는 좌표 없음. 제외 사유 문서화 필요 |
| 좌표 신뢰도 | 주소 기반 16, 시설 대용 2 | 주소 기반도 건물 기준점이라 맨홀과 수십 m 오차. 시설 대용 2곳은 더 큼 |
| 노드 ID | `23-0001` 형식 | 2025 데이터와 그래프 노드 ID 일치 검증 완료 [확정] |

**[미결정]** 좌표 신뢰도를 노드 속성(`coord_quality`: address / facility_proxy)으로 두고, 시설 대용 노드를 제외한 민감도 실험을 한다. 제외 시 16노드가 되어 그래프가 더 희소해진다는 점을 감수해야 한다.

## 2. 그래프 구성

현재 [확정]: 도로망 최단거리 기반 무방향 k-NN(k=2,3,4), 합집합, 반경 500m.

고려사항:
- **물리적 타당성 [위험]**: 하수는 상류→하류로 흐른다. 도로 근접은 관로 연결과 무관할 수 있다. 같은 도로 위 두 센서가 서로 다른 관로 계통(배수구역)에 속할 수 있다.
- 가능한 대안 (확보 가능성 순):
  1. 데이터 기반 그래프: 수위 상관/시차 상관이 높은 쌍을 연결. 단 학습 구간 데이터로만 계산(누수 방지). **T1 분석용으로만 사용한다. T2에서는 관측이 없는 노드의 상관을 계산할 수 없어 사용 불가.**
  - **T2용 엣지 규칙:** 관측 없이 정의 가능한 것(거리, 같은 구, 배수구역, 고도차)만 허용한다.
  2. 배수분구/하수처리구역 경계 데이터가 있으면 같은 구역끼리 연결.
  3. DEM으로 지표 흐름 방향 근사 (DEM 확보 필요, 지표 흐름이 관로 흐름과 같다는 가정 추가).
  4. 관로망 GIS (서울시 하수관로 공간정보). 확보되면 가장 좋지만 접근성 미확인.
- 간선 속성: 도로거리(m), 직선거리, 우회비. 거리 가중치 함수(가우시안 등)는 학습 전 고정.
- k=3 그래프에는 긴 간선 1개(23-0003 — 23-0006, 3,274m)가 있다. 이 간선을 두고 민감도 비교.
- 대조군: 랜덤 간선 그래프, 간선 없는 그래프(MLP 동치), 완전 연결 그래프. 이 3개가 있어야 "그래프의 구조가 효과가 있는가"를 말할 수 있다. [확정: 랜덤 재배치만 계획됨, 나머지 추가 필요]

**[미결정]** 방향 그래프 사용 여부. Phase A 시차 상관 결과로 결정.

## 3. 시간축·샘플링

| 항목 | 현재 | 고려사항 |
|---|---|---|
| 해상도 | 1분 [확정] | 1분 샘플은 연속 샘플 간 거의 동일 → 사실상 독립 표본 수가 보이는 수의 수십 분의 1. 학습은 stride 5~10 사용 검토 |
| 입력 창 | 60분 [확정] | 강우-수위 지연이 이보다 길면 부족. 강수 입력은 더 긴 누적(3h, 6h) 필요할 수 있음 |
| 예측 지평 | 10, 30분 [확정] | 대시보드의 의미 있는 선행시간(경보 대응)이 무엇인지 목적과 맞는지 확인 |
| 기간 | 2025-06~08 3개월 | 강우 이벤트 수가 결정적. 다른 연도/계절 데이터를 추가 확보할 수 있는지 확인 (원본이 연도별로 있는지) |

**[위험]** 3개월·한 해는 일반화 주장에 매우 약하다. 가능하면 2024년(또는 2023년) 같은 우기 데이터를 추가 확보해 "다른 해에서 검증"을 최종 테스트로 쓰는 것이 가장 강력하다. 원본 파일 구성을 먼저 확인할 것.

## 4. 결측 처리 [확정 + 보완 필요]

현재 원칙은 좋다: 원본 불변, 마스크 채널 분리, 정답에는 채운 값 금지, 인과적 LOCF 5분 보조안.

보완:
- 전 노드 동시 결측 83분(06-17 15:55~17:17)이 **강우 이벤트와 겹치는지** 확인한다. 겹치면 이벤트 중요 구간이 비어 있는 것이다.
- 23-0009 51.5시간 결측은 고수위 후 발생. MNAR(결측이 값에 의존)일 수 있으므로 이 노드의 결측 구간을 평가에서 어떻게 다루는지 서술.
- strict_raw 학습 샘플 탈락 4.3% vs masked 사용: 어느 쪽을 주 실험으로 쓸지 고정. 현재 `masked`(입력 결측 허용 + 마스크 채널)가 정보 손실이 적다.
- 결측 시뮬레이션(입력 일부를 인위적으로 가림)은 T2의 사전 연습이 된다.

## 5. 정규화·스케일 [확정 + 위험]

- 학습 구간 원본 관측값만으로 노드별 평균/표준편차. 누수 없음 [확정].
- **[위험]** 23-0014는 90%가 0m, std 0.0235. 23-0001은 std 0.0091. 정규화하면 미세 변동이 크게 증폭되어 손실을 지배할 수 있다. 대안: std 하한(floor) 설정, 또는 Huber 손실, 또는 노드별 가중 손실.
- 평가는 항상 **원 단위(m)** 로 역정규화해 보고. 정규화 공간 오차는 노드 간 비교가 불가능.
- 노드별 정규화는 T2(새 노드)에서 문제가 된다. 센서가 없는 노드의 평균/표준편차는 알 수 없다. T2에서는 노드 정규화 없이 전역 정규화를 쓰거나, 이웃 통계로 대체하는 규칙이 필요하다. **[미결정]**

| 변수 | 상태 | 우선순위 | 비고 |
|---|---|---|---|

| 관로 제원(관경, 관저고, 경사) | 없음 | 중~상 | "위험"의 절대 기준을 정하려면 필요. 공개 여부 미확인 |

## 7. 분할 설계 [핵심]

### T1 (시간 예측)
- 현재: 시간순 70/15/15, 경계 purge [확정]. 좋은 설계다.
- **[위험]** 분할이 달력 비율이어서 이벤트 분포를 통제하지 않는다. 최고수위 집중일(07-17)이 train에 있어 test에는 고수위 사건이 적다.
- 권장: 강우 이벤트를 단위로 하는 블록 교차검증. 이벤트 N개가 충분하지 않으면 expanding-window 시간 교차검증.
- validation은 하이퍼파라미터·조기종료에만, test는 마지막에 한 번만. 지금까지 test 수치를 이미 봤으므로, 이후 설정 변경을 test 보고서 기반으로 하지 않도록 규율을 둔다.

### T2 (공간 추정)
- 노드 단위 분할: leave-one-node-out(18-fold)이 기본. 모든 노드가 한 번씩 test가 된다.
- 시간 분할도 병행: train 노드 × train 시간, 검증은 held-out 노드 × test 시간. 두 축 누수를 모두 막아야 한다.
- 그래프에서 held-out 노드를 어떻게 다루는가:
  - 학습 시: 해당 노드를 그래프에서 제거하고(혹은 입력 마스킹) 나머지로 학습.
  - 추론 시: 해당 노드를 그래프에 추가(이웃 연결은 좌표 기반 규칙으로 생성, 정답 수위는 사용 안 함).
  - 이웃 선택 규칙이 학습 때와 추론 때 같아야 한다.
- **[위험]** held-out 노드 선택이 평가를 좌우한다. 이웃이 가까운 노드는 쉽고, 외딴 노드(23-0006: 최근접 2,238m)는 어렵다. 노드별 결과를 모두 보고하고 "이웃 거리 vs 오차" 관계를 보여 준다.

## 8. 타깃과 위험 라벨

- 연속 타깃: 수위(m). 손실은 관측된 칸만 평균 [확정].
- 위험 라벨 후보:
  1. 노드별 학습 구간 분위수 초과(현재 q95/q99): 상대 기준. 침수와 무관.
  2. 관로 만관 대비 수위비(관경 확보 시): 물리적 기준.
  3. 실제 침수 신고/이력(서울시 침수 흔적도, 민원): 공개 자료 접근성 확인.
  4. 수위 상승 속도 기준(급상승): 경보 지표로 현실적.
- **[미결정]** 확보 가능한 자료에 따라 선택. 어떤 경우든 라벨 정의는 결과를 보기 전에 고정하고 문서화한다.

## 9. 평가 설계

| 지표 | 목적 | 주의 |
|---|---|---|
| MAE, RMSE (m) | 전체 오차 | 평상시가 지배. 단독으로 쓰지 않는다 |
| 이벤트 구간 MAE/RMSE | 위험 관련 성능 | 이벤트 정의를 사전 고정 |
| 피크 오차(최대 수위, 도달 시각) | 경보 관점 | 이벤트별 1점이므로 표본 수 적음 |
| 초과 탐지: precision, recall, F1, PR-AUC | 위험 판정 | 불균형 심함. 정확도(accuracy) 금지 |
| 노드별 결과 | 이질성 | 평균 뒤에 숨은 실패 노드 확인 |
| 시드 반복 평균±표준편차 | 안정성 | 5회 이상 |

Baseline 계층 (모두 같은 평가쌍으로 비교) [확정 + 확장]:
- T1: persistence, 노드별 Ridge AR [확정], +강수 포함 모델, +GBM.
- T2: 노드 전체 평균, IDW, 선형 회귀, GBM, **그 다음에 GNN**.
- **GNN 주장의 조건:** 가장 강한 비-GNN baseline을 이긴다. 못 이기면 못 이겼다고 쓴다.

통계: 이벤트 수가 적으므로 부트스트랩(이벤트 단위 재표집) 신뢰구간을 보고. 평가쌍 35만 개는 독립 표본이 아니다.

## 12. 알려진 한계 (발표·보고서에 그대로 쓸 수 있는 문장)
