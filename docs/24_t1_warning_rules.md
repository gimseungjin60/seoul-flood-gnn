# 24. 30분 전에 큰 상승을 잡을 수 있나: 사전 고정 규칙

고정일: 2026-11-14. **T1 예측 파일이 만들어지기 전이고, T1 판정(docs/17)도 보기 전에** 정했다. 코드 기준은 [src/analysis/t1_warning_rules.py](../src/analysis/t1_warning_rules.py)의 상단 docstring과 상수다. 이 문서와 코드가 다르면 코드가 우선한다.
범위: 서울시 강남구 센서 (2026, T1 예측 대상 17개, 평가 이벤트 13개).

## 왜 하나
- T1 판정은 평균 오차(이벤트 MAE)로 한다. 하지만 실제로 쓸 때의 질문은 **"30분 뒤 큰 상승이 오는지 미리 알 수 있나"**다.
- 같은 T1 예측을 상승 단계([docs/16](16_rise_levels.md)) 기준으로 다시 본다. T1 판정 F1~F5는 바꾸지 않는다.

## 방법
| 항목 | 내용 |
|---|---|
| 상승폭 | 수위 − 센서별 요일×시간대 중앙값(평소 수위, docs/16과 같은 정의). 실제와 예측에서 같은 평소 수위를 뺀다 |
| 도달 사례 | (센서, 이벤트)에서 실제 상승이 **처음 200 mm 이상('큰 상승')이 되는 순간**. 단, 예측을 내는 30분 전 시점에 이미 200 mm 이상이었던 경우는 뺀다 |
| 맞힘 | 그 순간에 대한 30분 전 예측이 200 mm 이상 |
| 비도달 사례 | 이벤트 내내 실제 상승이 200 mm 미만 |
| 헛경보 | 비도달 사례에서 예측이 한 번이라도 200 mm 이상 |
| 점수 (CSI) | 맞힘 / (도달 사례 + 헛경보). 높을수록 좋다 |

- **처음 도달하는 순간만 보는 이유:** 단계는 한번 오르면 한동안 유지된다. 그래서 모든 10분을 세면 "직전 값 그대로"도 점수가 높게 나온다. 처음 도달하는 순간에는 "직전 값 그대로"가 정의상 항상 놓친다.
- **헛경보를 넣는 이유:** 무조건 높게 예측하는 모델이 이기지 않게 하려는 것이다.
- 실행 전 자료 확인(모델 결과 아님): 도달 사례 94개, 비도달 사례 127개.

## 판정 (이 두 가지뿐, 30분 뒤, 200 mm)
이벤트 13개를 2000회 복원추출(시드 0)하고, 차이의 95% CI로 판정한다.

| | 비교 | 판정 |
|---|---|---|
| W1 | CSI(G-road) − CSI(M2 강우+자기이력 선형) | 하한 > 0 "GNN이 더 잘 잡음" / 0 포함 "구분 불가" / 상한 < 0 "GNN이 선형보다 못 잡음" |
| W2 | CSI(G-corr) − CSI(M2) | W1과 같음 |

참고(판정에 쓰지 않음): 모델별 맞힘률·헛경보율·CSI, M3 − M2, 10분 뒤, 500 mm('매우 큰 상승').
