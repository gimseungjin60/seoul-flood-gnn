# 04. 중간발표 안 B: 데이터셋을 빼는 구성

**언제 쓰는가:** 청중이 데이터 구축 과정보다 **문제 설정·접근법·기대 효과·모델 결과**를 보고 싶어 할 때, 또는 데이터 작업이 이미 이전 발표에서 다뤄졌을 때. 모델 결과가 의미 있게 나온 경우에 가장 효과적이다.
**핵심 메시지:** "이 문제는 풀 가치가 있고, 이 방법이 맞는지 이렇게 검증하고 있으며, 지금 이만큼 알게 됐다."

**현재 상태에서의 솔직한 판단:** 데이터셋을 빼면 보여줄 모델 성과가 기준 모델(차이가 작음)뿐이다. **발표 전에 Phase A(공간 신호 진단)나 GNN 첫 결과를 확보하지 못하면 이 안은 알맹이가 부족해진다.** 결과가 없는 상태에서 데이터를 빼고 발표하면 "한 게 없어 보이는" 위험이 안 A보다 크다.

발표 시간은 미확인. **10분** 기준.

---

## 1. 발표의 논지 (한 문장)

> 하수관로 수위 센서가 없는 지점의 침수 위험을 알기 위해, 센서 간 공간 관계를 그래프로 표현하고 GNN으로 추정하는 방법을 검증한다. 우리는 "공간 정보가 실제로 도움이 되는가"를 가장 단순한 baseline과 비교해 판정하는 실험 구조를 설계했다.

## 2. 슬라이드 구성 (10분, 12장 이내)

| # | 제목 | 시간 | 내용 |
|---|---|---|---|
| 1 | 문제 | 1:00 | 침수 피해, 센서의 희소성, "센서 없는 곳은 모른다" |
| 2 | 왜 어려운가 | 0:45 | 센서 일부만 존재, 하수 흐름의 물리적 구조, 강우 의존성 |
| 3 | 접근 아이디어 | 1:00 | 센서를 노드로, 근접 관계를 간선으로. GNN으로 미관측 노드 추정. 그림 한 장 (fig1) |
| 4 | 연구 질문 3개 | 0:45 | Q1 공간 정보가 수위를 설명하는가 / Q2 GNN이 단순 방법보다 낫나 / Q3 센서 일부를 가릴 때 얼마나 버티는가 |
| 5 | 실험 설계 | 1:15 | T1(시간 예측), T2(센서 제거 추정), baseline 계층, 가장 강한 baseline을 이겨야 주장 가능 |
| 6 | 평가 방식 | 0:45 | 이벤트 단위, 피크 오차, 초과 탐지, 시드 반복. "평균 MAE만으로는 부족하다" |
| 7 | 현재까지의 결과 ① | 1:15 | baseline 결과(persistence ≈ Ridge). **차이가 작다는 점**과 그 해석(수위 관성이 지배, 강수 정보 부재) |
| 8 | 현재까지의 결과 ② | 1:15 | **(필수 보강)** 공간 신호 진단 or GNN 첫 결과. 이게 없으면 발표 중심이 비게 된다 |
| 9 | 한계와 위험 | 0:45 | 근접 그래프 ≠ 하수관, 18노드, 3개월, 강수·위험 라벨 미비 |
| 10 | 향후 계획과 게이트 | 1:00 | 강수 결합 → 마스킹 실험 → 대시보드. 실패 시 대안 |
| 11 | 기대 산출물 | 0:30 | 위험도 지도(Streamlit+Folium) 목업 |
| 12 | 마무리 | 0:15 | 질문 받기 |

데이터셋 관련 내용(수집·정제·결측·분할·좌표)은 **부록으로만** 둔다. 질문이 나오면 꺼낼 수 있도록 준비하되 본 발표에서는 한 슬라이드(5번)에서 "시간순 분할, 정답은 원본 관측값만 사용"으로 요약한다.

## 3. 데이터를 빼도 지켜야 하는 것

데이터셋을 본 발표에서 생략하더라도 **결과의 신뢰성을 위한 최소 정보는 반드시 남긴다.** 그렇지 않으면 결과 해석이 불가능하다.

- 노드 수(18), 기간(3개월), 시간 간격(1분)
- 분할 방식(시간순, 누수 방지)
- 정답은 실제 관측값만 사용
- 그래프는 근사임

이 4줄은 슬라이드 5 또는 7의 각주로 넣는다.

## 4. 이 안의 강점과 약점

강점
- 이야기가 연구 질문 중심으로 흐르고 청중이 이해하기 쉽다.
- 데이터 작업 설명 시간을 모델/실험 설명으로 돌릴 수 있다.
- 한계를 "다음 실험의 동기"로 연결하기 좋다.

약점 (각오할 것)
- 슬라이드 7, 8에 보일 내용이 현재 약하다. 첫 baseline은 "차이 미미"이고 GNN 결과는 없다.
- 3주 동안 한 가장 큰 작업(데이터 구축)이 보이지 않는다. 평가자가 작업량을 과소평가할 수 있다. → 부록과 한 줄 요약("원본 2,256만 행 → 18노드 × 132,480분 정제")으로 보완.
- 연구 질문과 실험 설계만 있고 근거가 없으면 "계획만 있는 발표"로 보인다.

## 5. 성립 조건 (발표 전 반드시 확보)

다음 중 **최소 1개**가 없으면 안 A로 전환할 것을 권한다.

1. Phase A 결과: 거리-상관 감쇠 그림 + leave-one-out IDW/선형 baseline 결과
2. 강수량을 결합한 baseline 개선 결과
3. GCN/GraphSAGE 첫 학습 결과 (baseline과의 비교표 포함, 이겼든 졌든)

## 6. 예상 질문과 답변 방향

| 질문 | 답변 방향 |
|---|---|
| 데이터는 어떻게 구성했나? | 부록 슬라이드 사용. 18노드, 1분, 3개월, 시간순 분할. 상세 리포트가 저장소에 있다 |
| baseline 대비 개선이 거의 없는데? | 맞다. 평상시 값 지배 + 강수 미결합이 원인으로 추정되며, 이벤트 구간 지표로 따로 본다. 추정이지 확인은 아니다 |
| GNN 결과는? | (결과 있으면 그대로. 없으면) 아직 없다. 공간 신호 진단 결과로 진행 여부를 판단하는 게이트를 두었다 |
| 그래프가 실제 관로가 아닌데 의미 있나? | 한계로 명시. 상관 기반 대안과 비교 예정 |
| 대시보드에서 무엇을 보여주나? | 실측/예측 비교, 추정 신뢰도, 센서 없는 지점은 "추정"으로 구분 표시. 위험 정의는 자료 확보 후 확정 |
| 실제 침수와의 관계는? | 현재 수위 기반이며 침수 이력 자료와는 연결되지 않았다. 침수 흔적도 등 외부 자료 연결 가능성을 검토한다 |

## 8. 안 A와 안 B 선택 가이드

| 상황 | 권장 |
|---|---|
| 발표일까지 새 결과가 없다 | **안 A** (데이터 구축 성과가 유일한 확실한 자산) |
| Phase A 결과는 있고 GNN은 없다 | 안 A + Phase A 슬라이드 1장 추가, 또는 안 B (결과가 한 장이라도 중심이 될 수 있음) |
| GNN과 baseline 비교 결과가 있다 | **안 B** (결과 중심, 데이터는 부록) |
| 청중이 데이터 전문가 중심이다 | 안 A |
| 청중이 도메인/응용 중심(방재, 행정)이다 | 안 B |
| 심사 기준에 "데이터 수집·가공"이 명시되어 있다 | 안 A (또는 안 B에 3장 추가) |
