## 3. 냉정한 문제 진단

### P1. 목표와 지금까지의 실험 설계가 어긋나 있다 (가장 큰 문제)
- 프로젝트 목표: **센서가 없는 지점**의 수위 추정.
- 현재 데이터셋/기준 모델: **센서가 있는 18개 지점의 미래 값**(시간 외삽) 예측.
- 이 둘은 다른 문제다. 전자는 공간 보간(inductive, leave-node-out), 후자는 시계열 예측이다.
- 지금 설계로 GNN을 학습시켜 baseline을 이겨도 "센서 없는 지점을 예측한다"는 주장은 못 한다. Masking 실험(역할표상 최진호 담당)이 핵심 실험이어야 하는데 로드맵상 맨 뒤에 있다.

### P2. 18노드 그래프에서 GNN이 이길 근거가 약하다
- 노드 18개, 최근접 이웃 도로거리 중앙값 708m, 지점쌍 중앙값 4,042m. 1분 단위 수위 상관이 이 거리에서 유지된다는 확인이 없다.
- 그래프는 "도로 근접"이지 하수관 연결이 아니다. 상·하류 방향이 없다. 하수 수위는 관로 위계(상류→하류)가 지배적이므로, 도로 근접 간선이 물리적 의미를 갖는다는 가정은 **검증되지 않은 가정**이다.
- 반경 500m 그래프는 18노드 중 10개가 고립이다. 즉 대부분 지점은 500m 안에 이웃이 없다.
- 이미 Ridge(이웃 정보 없음)가 persistence를 거의 못 이긴다. 이웃 정보 없이 시간 정보만으로도 개선 여지가 작은데, 이웃을 넣는다고 큰 개선이 나올 것이라는 기대는 근거가 없다.

### P3. 평가 데이터에 "위험 사건"이 충분하지 않을 가능성이 높다
- 분할이 시간순이라 test는 2025-08-18~08-31 (14일). 수위 최고치 집중일은 07-17로 **train 구간**이다.
- test의 q99 평가쌍은 2,966개(h=10)인데 연속된 몇 개 이벤트에서 나온 자기상관 높은 표본이다. 독립 표본이 아니다. 통계적 유의성을 주장할 수 없다.
- 평균 MAE 0.007m는 대부분 평상시(건천 상태) 값이다. 침수 예측 시스템의 성능 지표로는 거의 정보가 없다.

### P4. 강수량이 없다
- 하수관 수위는 강우의 함수다. 강우 없이 수위만으로 하는 예측은 "수위 관성"만 학습한다. persistence가 강한 이유다.
- 기상청 ASOS/AWS 확보가 로드맵에서 가장 우선순위가 높은 미해결 항목인데, 아직 시작하지 않았다.

### P5. "침수 위험"의 정의가 없다
- 수위(m)를 예측하는 것과 침수 위험을 판정하는 것은 다르다. 수위가 관로 높이/지표면 대비 어느 수준이면 위험인지 기준(관경, 관저고, 맨홀 지반고, 만관율)이 없다.
- 현재는 노드별 분위수(q95/q99)를 "고수위"로 정의했는데 이는 상대 지표이지 위험 기준이 아니다. 노드 수위가 0.7m 평균인 23-0008과 0.004m 평균인 23-0014의 q99는 위험 의미가 전혀 다르다.
- 대시보드의 "위험도"를 무엇으로 계산할지가 비어 있다.

### P6. 데이터 품질 이슈가 모델링에 아직 반영되지 않았다
- 23-0014: 0m 비율 88~90%, 좌표도 시설 대용. 사실상 이진에 가까운 노드. 정규화 시 std가 작아 오차가 확대된다.
- 23-0001: std 0.0091로 매우 작음.
- 23-0009: 고수위 기간 직후 51.5시간 결측. 결측이 수위와 독립이라고 가정할 수 없다.
- 전 노드 동시 결측 83분: 수집 시스템 문제 추정. 사건 한가운데(06-17)에 걸려 있을 수 있어 확인 필요.
- 좌표 2곳 대용 + 2곳 미확정 = 20개 중 4개(20%)가 위치 불확실. 공간 모델의 입력인 "위치" 자체가 흔들린다.

### P7. 문서·우선순위 편향
- 리포트·검증·재검증 코드는 풍부한데(좋은 습관이다) 모델/실험 코드는 없다. 앞으로 2~3주는 "검증 보고서 추가"보다 "결과가 나오는 실험"에 우선순위를 둬야 한다.
- `README.md`는 아직 "현재 Week 1" 기준이다. 문서와 현실이 불일치한다.
- 테스트 파일은 모듈마다 있으나 이번 평가에서 실행 결과는 확인하지 않았다 (재실행 필요).

## 4. 잘 한 점 (유지할 것)

- 원본 불변 원칙, 가공물은 `processed/`에만.
- 시간순 분할 + purge, 정답은 원본 관측값만, 마스크 채널 분리. 데이터 누수 방지가 설계 수준에서 되어 있다.
- 정규화 통계를 학습 구간만으로 계산.
- [사실]/[추정] 구분. 원인 미확인 사항을 사실처럼 쓰지 않는 태도.
- GNN 비교용 공통 평가쌍과 랜덤 간선 대조군 설계. 이 설계를 실제로 실행하기만 하면 된다.
- 좌표를 만들어내지 않고 NOT_FOUND를 그대로 둔 점.

## 5. 로드맵

핵심 원칙: **"GNN이 가치가 있는가?"를 가장 싼 실험으로 먼저 판정하고, 그 결과에 따라 프로젝트의 서술을 정한다.**
GNN이 이기지 못해도 프로젝트는 실패가 아니다. "18개 하수 수위 센서에서 그래프 정보가 도움이 되는가/안 되는가"를 정량화한 결과가 곧 결과물이다. 다만 사전에 기준을 정해 두어야 한다.

중간발표일은 아직 확인되지 않았다. 아래는 4주차를 시작점으로 한 상대 일정이며, 발표일이 정해지면 단계 간 컷오프만 조정한다.

### Phase A. 공간 신호 존재 여부 진단 (4주차, 모델 학습 전)
GNN을 쓰기 전에 "이웃이 정보를 주는가"를 확인한다. 저비용이며 결과에 따라 이후 전체가 바뀐다.
1. 노드 쌍 간 상관(1분 → 10분 평균 처리 후) vs 도로거리 산점도. 거리-상관 감쇠가 있는가.
2. 이벤트 구간(07-17 등) 한정 상관과 평상시 상관을 분리.
3. 시차 상관(cross-correlation lag). 상·하류 지연이 보이면 방향성 그래프의 근거가 된다.
4. 한 노드를 빼고 나머지 17개로 추정하는 **비그래프 baseline** 구현:
   - 이웃 평균/가중평균(IDW), 전체 노드 평균 회귀, 선형 회귀(나머지 17개 → 대상 1개).
5. 판정 기준을 미리 적어 둔다 (예: "leave-one-out에서 IDW가 노드 평균 대비 MAE 10% 이상 개선되지 않으면 도로 근접 그래프 가정은 기각").

**산출물:** 진단 그림 3~4장 + 한 페이지 결론. 이 결과가 중간발표의 핵심 슬라이드가 된다.

> **2026-10-17 완료.** 결과는 [05_spatial_signal_result.md](05_spatial_signal_result.md). 판정: 공간 정보는 있으나(Ridge 17개 입력이 상수 대비 0.50배) 거리 기반 근접 그래프의 근거는 약함(Mantel -0.17, IDW가 단순 평균과 비슷). G1 부분 통과: GNN 진행은 가능하나 그래프를 도로 k-NN 하나로 고정하지 않고 완전 연결·무간선·랜덤과 함께 비교한다(상관 기반 그래프는 T2에서 쓸 수 없어 T1 분석용으로만 남긴다).

### Phase B. 강수량 확보 (4주차와 병행)
1. 기상청 방재기상관측(AWS)/ASOS에서 강남·서초 인근 지점의 2025-06~08 분/시간 강수량.
2. 가장 가까운 관측소 선택 근거 기록, 시간축 정렬, 결측 처리.
3. 수위-강수 시차 상관 확인.
4. 강우 이벤트 정의(예: 시간 강수량 임계, 이벤트 간 무강우 간격)와 목록화. 이벤트가 몇 개인지가 이후 평가 설계를 결정한다.

**리스크:** 이벤트 수가 3~5개 이하이면 분할 방식 자체를 이벤트 단위로 바꿔야 한다.

> **2026-10-18 완료.** 결과는 [06_rainfall_data.md](06_rainfall_data.md). 유의 이벤트 10개(train 6 / val 2 / test 2)로 게이트 G2는 통과하지만, 50mm 이상 큰 사건은 2개뿐이고 test에는 45mm짜리 하나만 의미 있다. 수위는 강우에 10분 안팎으로 반응한다. 센서별 최근접 강우량계 배정도 끝냈다(강남 평균보다 상관이 높은 센서 13/18, 개선 폭은 작음).

> **2026-10-18 강우 효과 확인 → [07_rain_effect_results.md](07_rain_effect_results.md).** 선형 Ridge에 강우 특징을 더해도 사전 규칙(test 전체 MAE 5%↑, test 이벤트 MAE 10%↑)을 충족하지 못했다(이벤트 MAE는 네 설정 모두 -3.6~-10.4%). 이벤트는 val 2개·test 2개 사건에 의존한다. 강우를 제거한 공간 진단 2차의 결론: **약한 거리 구조가 있으나 사전 기준(-0.30) 미달**(Spearman -0.23). 상관 기반 그래프는 T2에서 쓸 수 없어 철회했다.

> **2026-10-18 T2 LOSO 진단 → [08_t2_loso_diagnosis.md](08_t2_loso_diagnosis.md).** 센서 1개를 통째로 빼고(타깃 과거값 미사용) 이웃의 현재 값으로 추정: 사전 기준(이벤트 MAE 10%↑ 센서 6개 이상) **충족 10/18 → T2 공간 신호 있음**. 단서: 기준선(강우+시간대)이 약해 단순 평균·IDW도 같은 수준이며, 학습 모델 (4)(5)는 IDW를 이기지 못했다(IDW 평균 이벤트 MAE 0.0253 vs (4) 0.0263, (5) 0.0266). 일주기(요일×시) 제거는 결론을 바꾸지 않았다(Spearman -0.23~-0.25, 사전 기준 미달). GNN 준비는 하지 않는다.

### Phase C. 실험 설계 재정의 (5주차 초)
Phase A/B 결과로 아래를 확정한다. 문서 `02_dataset_design.md`의 "미결정 항목"을 모두 결정한다.
- 과제를 둘로 분리한다.
  - **T1 시간 예측**: 센서 있는 노드의 t+h 수위 (현재 데이터셋).
  - **T2 공간 추정**: 센서를 제거한 노드의 수위 (leave-node-out / 마스킹). 프로젝트 목표와 직접 대응.
- 평가 단위를 "전체 평균"에서 "이벤트 단위 + 피크 오차 + 초과 탐지(분류)"로 바꾼다.
- "위험"의 정의 확정 (절대 수위 기준 확보 가능 여부 확인, 불가능하면 노드별 상대 기준임을 명시).

### Phase D. 모델 (5~7주차)
작은 것부터 순서대로, 각 단계마다 이전 단계 대비 이득을 표로 남긴다.
1. T2용 비-GNN baseline (IDW, 선형/Ridge, GBM). **GNN은 이 baseline을 이겨야만 의미가 있다.**
2. 강수량을 넣은 노드별 모델 (공간 정보 없이 강수만으로 얼마나 되는가).
3. GCN 또는 GraphSAGE (k=3 기본, k=2/4 민감도). 작은 모델(은닉 16~32, 2층)부터. 18노드에서 큰 모델은 과적합만 늘린다.
4. 랜덤 간선 대조군, 거리 가중 vs 비가중.
5. Masking 실험: 1개 노드 제거(18-fold leave-one-node-out), 이후 2~3개 동시 제거.
6. 시드 5개 이상 반복, 평균±표준편차 보고.

### Phase E. 위험도 표현·대시보드 (7~8주차)
- Phase C에서 정한 위험 정의로 노드별 위험 등급 산출.
- Streamlit + Folium: 실제/예측 비교, 불확실성(신뢰도) 표시, 데이터 한계 고지.
