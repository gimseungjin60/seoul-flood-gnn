# 30. 60분 뒤 GNN 우위는 이웃 덕분인가, 재현되나: 사전 고정 규칙

고정일: 2026-11-14. **[docs/28](28_t1_long_result.md) 판정과 사후 오차 분해를 본 뒤이고, 이 실험의 어떤 모델도 돌리기 전에** 정했다. 코드 기준은 [src/analysis/t1_nbr_rules.py](../src/analysis/t1_nbr_rules.py)다. 문서와 코드가 다르면 코드가 우선한다.
범위: 서울시 강남구 센서 (2026, 예측 대상 17개 + 입력 센서 31개, 평가 이벤트 13개).

## 이미 아는 것
- 입력 120분·60분 뒤에서 G-road − M2는 −1.58 mm [−3.13, −0.30]였고, G-corr − M2는 −1.38 [−2.78, −0.13]이었다. 둘 다 "GNN이 넘음"이다.
- 사후 분해에서 GNN의 이점은 물이 빠지는 구간에 몰려 있었다.
- 이웃 없는 GNN의 결과와 다른 시드의 결과는 아직 모른다.

## 왜 하나
1. GNN이 이긴 이유를 가른다. **이웃 정보(그래프)** 덕분인지, **비선형 시간 모델(GRU)** 덕분인지 확인한다.
2. 시드를 바꿔도 우위가 남는지 본다. docs/28의 CI 상한이 0에 가까웠기 때문이다.

## 설정
[docs/26](26_t1_long_rules.md) 확장과 모두 같다(입력 120분, 30·60분 뒤).

| 모델 | 내용 |
|---|---|
| G-none | G-road와 구조·학습·시드(0·1·2)가 같고, **인접 행렬만 0**이다. 각 센서는 자기 이력·강우·시간대만 본다 |
| G-road (시드 3·4·5) | G-road와 같고 시드만 다르다 |
| M2, G-road (시드 0·1·2) | docs/28 실행의 예측을 그대로 쓴다 |

- 구현: `t1_st.road_graph`를 0 행렬로 바꾸기만 한다. T1 코드는 고치지 않았다.
- 테스트: [tests/test_t1_nbr.py](../tests/test_t1_nbr.py)에서 다음을 확인한다.
  - 0 그래프면 다른 센서 값이 예측에 섞이지 않는다.
  - 미래 값이 누수되지 않는다.

## 판정 (이 세 가지뿐, 60분 뒤, 이벤트 MAE)
| | 비교 | 판정 |
|---|---|---|
| N1 주 | G-road − G-none | 상한 < 0 "이웃 그래프가 기여" / 0 포함 "구분 불가" / 하한 > 0 "이웃을 넣으면 나빠짐" |
| N2 주 | G-none − M2 | 상한 < 0 "이웃 없는 GNN도 선형을 넘음" / 0 포함 "구분 불가" / 하한 > 0 "선형보다 나쁨" |
| R1 재현 | G-road(시드 3·4·5) − M2 | 상한 < 0 "재현됨" / 0 포함 "재현 안 됨" / 하한 > 0 "선형보다 나쁨" |

**해석 (미리 정함)**
- N1이 "기여"면 docs/28의 우위를 그래프 효과로 보고한다.
- N1이 "구분 불가"이고 N2가 "넘음"이면, 우위는 시간 모델 효과로 보고하고 그래프 효과로는 보고하지 않는다.
- 둘 다 "구분 불가"면 어느 쪽 덕분인지 가릴 수 없다고 보고한다.
- R1이 "재현 안 됨"이면 docs/28 결과가 시드에 민감하다는 점을 함께 적는다.

참고(판정에 쓰지 않음): 30분 뒤의 같은 비교, G-corr − G-none, 두 시드 묶음 사이의 차이.
